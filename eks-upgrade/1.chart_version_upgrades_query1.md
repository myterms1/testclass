How do i know what chart versions upgrades are required for the eks v1.36?
====

You find out by checking each chart against the new Kubernetes version. Charts fall into three groups, and each group has its own check.

## 1. Charts that must match the Kubernetes minor version

These are built for one specific Kubernetes release, so they **must** be bumped with every hop:

- **cluster-autoscaler:** the image tag must match the cluster (v1.36.x for 1.36). ✅ You already do this.
- **descheduler:** its version number follows Kubernetes (0.34 ↔ 1.34). You're on 0.34.0. Descheduler v0.36.0 is out, and its release prep bumped the Kubernetes dependencies and the CI test matrix. **Set it to 0.36.x** in your eks-addons tfvars, the same way you override cluster-autoscaler.

## 2. Charts with a published support matrix

These projects state which Kubernetes versions they test. Check each chart's README or docs before every hop:

- **ingress-nginx — the real risk.** The project's own table lists ingress-nginx v1.14.0 (chart 4.14.0) as supported only on Kubernetes 1.30 to 1.34. The project is also retired, though existing deployments will keep working. So on 1.36 you're running **untested and unsupported**. It works in dst today, but this is the strongest reason to plan the migration off ingress-nginx before prd.
- **Kyverno:** ✅ already done (3.8.2 supports 1.33–1.36).
- **Check the matrix for:** cert-manager, external-secrets, aws-load-balancer-controller, keda, metrics-server, vpa.

## 3. Everything else

These charts rarely care about the Kubernetes version (goldilocks, node-problem-detector, csi-driver-smb, overprovisioner, windows-gmsa). Here you just check that nothing uses an API that 1.36 removed.

## How to check, step by step

**A. EKS upgrade insights (free, already there).** Before each hop, the console shows a "Deprecated APIs removed" check. It must be **Passing**.
```bash
aws eks list-insights --cluster-name gsm-dst-metal-eks-blue
```

**B. Ask each chart which Kubernetes versions it allows.** Many charts declare this in their `Chart.yaml` as `kubeVersion`. Use the chart repo URLs from the inventory doc:
```bash
helm show chart ingress-nginx --repo https://kubernetes.github.io/ingress-nginx --version 4.14.0 | grep -i kubeVersion
helm show chart kyverno --repo https://kyverno.github.io/kyverno --version 3.8.2 | grep -i kubeVersion
helm show chart oci://ghcr.io/deliveryhero/helm-charts/node-problem-detector --version 2.3.22 | grep -i kubeVersion
```
If the range excludes 1.36, the chart needs a bump. No output means the chart doesn't declare a range, so check its docs instead.

**C. Scan for removed APIs in what's installed.**
```bash
pluto detect-helm -A --target-versions k8s=v1.36.0
```
Anything marked **REMOVED** must be fixed before the hop.

**D. After the hop, confirm health.**
```bash
kubectl get pods -A | grep -vE "Running|Completed"
kubectl -n <namespace> logs deploy/<controller> --tail=50
```
Look for errors like `no matches for kind` or `the server could not find the requested resource`.
