# My Question: do you see any difference in the helm chart of 4.14.0 an 4.15.1 of ingress-controller? Will 4.14.0 or 14.15.1 will work with the v1.36 or it wont?
# Answer: 
I can compare the **controller** changes (I read the official 4.14 → 4.15 release notes), but not the Helm chart templates themselves. My sandbox has no internet, so I couldn't download both charts and diff them. Below is what I found, plus how to diff the charts yourself in two minutes.

## What changed from controller v1.14 (chart 4.14.x) to v1.15 (chart 4.15.x)

No breaking changes or removed settings are listed. The changes fall into three groups:

**1. Kubernetes support:** the project's test environment moved up to Kubernetes 1.35, and its Kubernetes libraries were bumped from 0.34 to 0.35. So 4.15 is built against Kubernetes one version newer than 4.14.

**2. Security hardening (worth testing):**
- the nginx template now quotes all `location` and `server_name` directives and escapes quotes and backslashes
- stricter regex checks on some annotations (auth method, `proxy-cookie-domain`), and annotation aliases are now included in risk evaluation
- the admission webhook now uses a 9 MB limit

These could reject an **unusual** annotation that 4.14 accepted. Normal Ingresses are unaffected.

**3. Fixes:** a sync bug when the host clock jumps forward, a crash on an empty `cpu.max` file, and a fix for SSL passthrough on hosts that were previously HTTP-only. Some of these were also backported to the 4.14.x patch releases.

## Will 4.14.0 or 4.15.1 work on 1.36?

**Neither is officially tested on 1.36.** In practice:

- **4.14.0 already works on 1.36. Your dst is proof.**
- **4.15.1 should work at least as well:** it's built against newer Kubernetes libraries and uses the same stable APIs (Ingress v1, Services, EndpointSlices), none of which 1.36 removed.
- What you lose either way is **future fixes**, not today's functionality.

So 4.15.1 is the better choice, as long as your dst test passes.

## Diff the two charts yourself (2 minutes)

```bash
# your real values
helm -n ingress-control get values ingress-nginx -o yaml > my-values.yaml

# render both versions with your values
helm template ingress-nginx ingress-nginx --repo https://kubernetes.github.io/ingress-nginx \
  --version 4.14.0 -n ingress-control -f my-values.yaml > v4140.yaml
helm template ingress-nginx ingress-nginx --repo https://kubernetes.github.io/ingress-nginx \
  --version 4.15.1 -n ingress-control -f my-values.yaml > v4151.yaml

diff v4140.yaml v4151.yaml

# default values changes
diff <(helm show values ingress-nginx --repo https://kubernetes.github.io/ingress-nginx --version 4.14.0) \
     <(helm show values ingress-nginx --repo https://kubernetes.github.io/ingress-nginx --version 4.15.1)
```

In the diff, image tags changing is expected. Anything touching the **Service** (ports, annotations, `type`) is what matters most, because that drives your NLB.

**Check your annotations against the stricter rules:**
```bash
kubectl get ingress -A -o yaml | grep "nginx.ingress.kubernetes.io" | sort | uniq -c
```
